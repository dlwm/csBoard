# 数据格式、视图库与操作 API 设计草案

对应 [Roadmap](../ROADMAP.md)。基线为 CSBoard **1.21.2**；本文中的模块名称、接口和事件均为拟议设计，尚未发布为 SDK。后续实现应先确认合同，再逐步迁移现有功能。

## 1. 三种合同分别维护

| 合同 | 职责 | 维护位置 |
| --- | --- | --- |
| Demo 数据合同 | 文件布局、人物与事件、轨道、单位、缺失值及扩展 | `dlwm/cs2-demo-format` fork，并向上游提 PR |
| 视图库合同 | 数据源、资源源、渲染、查询、操作、事件与生命周期 | 从 CSBoard 抽离的视图库 |
| AI 工具合同 | 将工具参数映射成公开操作，提供模型可读说明 | 可选 AI 适配层 |

数据格式不承担 AI 提示词、界面布局或应用权限管理。视图库核心不读取 CSBoard 全局平台、设置、存档目录、数据库或房间状态；宿主应用通过接口注入服务。

## 2. 解析驱动与数据适配器

- **驱动**负责解析会话、运行环境、输入句柄、进度、取消和资源释放。
- **适配器**负责人物身份、坐标、时间、事件、轨道与标准字段的转换。
- 同一个 Go 解析器的 native、WASM 和嵌入式运行共用适配器。其他解析器分别接入，不按 Electron/Web/Capacitor 再复制一套字段转换。
- 原始 `.dem`、标准交换包和内部缓存是不同的数据来源，通过同一个视图数据源接口提供片段目录、时间范围与按需轨道读取。

ZIP 用于交换、归档和分享；运行时按片段、回合或轨道加载。数据源支持取消读取、加载状态和缓存预算，不要求前端一次解压整场比赛。

### 数据语义与能力

- 明确 Source 坐标和渲染坐标的单位、轴方向及变换，不能把两种坐标混在同一个字段里。
- 显式声明 tick rate、采样率、时间原点、片段偏移及高精度输入的时间表示，不固定假设 64 tick 或 8 Hz。
- 人物身份不依赖显示名称；设计需覆盖 bots、掉线重连、人数变化和无法提供 Steam ID 的数据。
- 区分“支持但无事件”“未提取”“来源未提供”和“不适用”，不能把缺失值填成零再当成事实。
- 能力分别描述数据是否存在、视图库是否能展示、宿主是否允许操作。

### 与 fork、上游协作

优先为冻结阶段、自制录像/片段、投掷准备与输入动作、烟雾体素、火焰范围和语音设计可选能力。每项扩展需要字段语义、Schema、精简样例、校验规则与降级方式。

现有上游严格 Schema 不代表任意新字段已被允许；先约定扩展声明与兼容读取规则。库版本、格式版本、扩展版本和解析器版本分别记录。向上游提交小范围 PR，接受后同步 fork，避免永久维护两套标准。

## 3. 3D 视图库边界

| 模块 | 包含 | 外部注入或留给宿主 |
| --- | --- | --- |
| 渲染核心 | 地图/NAV、人物、道具效果、相机、层显示、选取 | 资源加载器、容器、渲染配置 |
| 回放控制 | 播放、暂停、跳转、插值、轨道消费 | 数据源、时间范围与加载策略 |
| 编辑控制 | 选中、拖动、人物/道具/路线修改、事务 | 许可策略和持久化 |
| 对外接口 | 操作、查询、能力、事件、销毁 | 应用按钮、快捷键和侧栏 |
| 集成适配 | 标准数据转换、可选 React 封装、AI 工具映射 | Yjs、会话记忆、模型服务、应用壳 |

先分离当前视图组件的渲染、数据和交互职责，再让 CSBoard 使用抽出的库。一个页面可拥有多个独立实例；每个实例的相机、选中状态、订阅和资源生命周期独立。

地图列表、点位名称、区域与出生点来自资源元数据，不把 CSBoard 的固定地图目录或存档格式作为第三方使用的前置条件。

## 4. 公共操作 API

建议统一为“命令、查询、订阅、宿主策略”四个入口。下面只是接口方向，不是现有可调用 API：

```ts
const viewer = createViewer({ container, dataSource, resourceLoader, policy });

const capabilities = viewer.getCapabilities();
const state = viewer.getState();
const result = await viewer.execute(
  { type: 'camera.set', camera: { /* documented camera fields */ } },
  { operationId, origin: 'api', expectedRevision: state.revision, signal },
);

const unsubscribe = viewer.on('selection.changed', event => {
  updateHostSelection(event.payload);
});

unsubscribe();
viewer.dispose();
```

### 操作范围

- 数据加载、回放控制、相机与二维/三维模式、显示与楼层。
- 人物、道具、路线、画笔和战术帧的查询与编辑。
- 坐标拾取、空间查询、截图与指定观察视角，按实际能力开放。
- 存档、房间和 AI 会话由宿主提供扩展命令，不作为核心库自带的数据库或网络操作。

核心与宿主扩展命令共用可发现的命令目录，声明命名空间、参数/结果 Schema、权限及所需能力。调用方可以据此生成 UI 或 AI 工具列表；不能把宿主特有命令伪装成每个视图库实例都支持的标准命令。

### 一致性与结果

- 读写共用同一对象 Schema；格式转换集中处理，不再让调用方猜位置字段的嵌套层级。
- 每个对象有稳定 ID；编辑操作携带 revision，状态过期时返回冲突信息。
- 批量编辑默认先整体校验再提交；失败不留下半次布阵，成功对应一次撤销。
- 结果区分成功、失败和取消，包含 operation ID、最终 revision、实际变化或规范化后的值。
- 错误包含稳定代码、字段路径、原因和可接受字段/示例；调用方不依赖英文错误字符串分支判断。
- 取消停止尚未执行的工作，不假装已完成操作被撤回；资源加载、任务取消与编辑事务分别定义边界。
- 回放加载和每帧更新不进入编辑撤销栈；共享会话中的撤销交由协作适配层处理，不覆盖其他人的修改。

### 宿主策略

可修改操作在提交前经过宿主策略，返回允许、拒绝或经过校验的替代命令。异步确认发生在命令流程，不阻塞渲染线程。回放帧和资源进度通知不需要逐次审批。

前置策略与事后事件分开。事件载荷不允许通过隐式修改来改变内部状态；调用方需要修改时使用公开命令。

## 5. 事件合同

拟议事件类别：

| 类别 | 事件示例 |
| --- | --- |
| 指针与选择 | `pointer.clicked`、`hover.changed`、`selection.changed` |
| 拖动 | `drag.started`、`drag.updated`、`drag.ended`、`drag.cancelled` |
| 编辑对象 | `objects.changed`、`frame.changed`、`history.changed` |
| 视图 | `camera.changed`、`viewMode.changed`、`layers.changed` |
| 回放 | `playback.started`、`playback.paused`、`playback.seeked`、`playback.timeChanged`、`playback.ended` |
| 资源 | `resources.progress`、`resources.ready`、`resources.failed` |
| 命令 | `operation.started`、`operation.completed`、`operation.failed`、`operation.cancelled` |
| 生命周期 | `viewer.ready`、`viewer.failed`、`viewer.disposed` |

### 公共事件信息

事件使用带类型的载荷，并携带实例 ID、事件 ID、实例内递增 sequence、来源和适用的 operation ID。涉及回放时显式附带播放时间；通知时间与 Demo 时间不能混用。

来源可区分用户、API、AI、回放和远端同步。operation ID 应贯穿命令、变更与完成通知，使宿主能够识别自身写入并避免重复回写。来源是追踪信息，不是安全权限证明。

### 投递与清理规则

- `on()` 返回取消订阅函数；销毁幂等，释放监听、任务和私有 GPU 资源，并拒绝后续操作。
- 镜头、拖动与播放时间支持按帧合并或节流；开始、结束、取消、失败及最终状态必须准确投递。
- 订阅默认不重放完整历史；调用方先查询状态，再按 revision/sequence 处理增量，避免查询与订阅之间漏掉变化。
- 同一事务完成后才发布已提交变更；跨实例不承诺全局事件顺序。
- 一个回调抛错不得阻断其他订阅者或撤回已完成事务；通过错误入口报告订阅者异常，避免递归报错。
- 回调内触发新命令时排队执行，不嵌套修改正在发布的事务。
- 多视图共享资源必须明确所有权或引用计数，一个实例销毁不能释放其他实例仍在使用的资源。

## 6. AI 是公共 API 的调用方

现有 AI 工具逐步改为公开 API 的适配器，不保留专用隐藏写入路径。工具参数与说明尽量从公共命令 Schema 生成，展示名称可国际化，稳定工具 ID 用于调用。

提示词、上下文压缩、长期记忆、工作流、服务登录和密钥不属于视图库。宿主可按事件记录用户操作，再选择性提供给自己的 AI；高频时间和拖动事件应汇总成最终结果，避免逐帧堆积上下文。

截图能力只返回请求的视图和必要元数据；视角、建筑显隐、尺寸与资源缺失状态显式声明。截图不应移动用户主相机，也不自动证明游戏内视线或道具有效性。

## 7. 文档、示例与验收目标

- 发布命令和事件目录、参数 Schema、结果与错误码、兼容矩阵、生命周期说明及迁移指南。
- 提供纯查看、可编辑、多个实例及 AI 调用的独立示例，不依赖 CSBoard 隐藏初始化。
- 字段对照覆盖正式对局、自制片段、冻结阶段、投掷输入、真实烟体和语音，明确可保真与降级的部分。
- 检查取消、重复销毁、加载失败、事件循环、订阅者异常和多个实例共享资源。
- 对比初始加载、内存、跳转、监视器和第一人称性能；抽库不得以明显性能回退换取接口统一。
- 数据格式和操作 API 分别遵循版本兼容规则；发布前明确沿用现有 GPLv3 或另行安排授权的范围。

先在 `feature/demo-format` 稳定数据接口，再在 `feature/viewer-library` 实现上述视图合同。对未来命令名、包名和扩展字段的调整，应同步本文及实际 Schema，不能只修改 AI 工具说明。
