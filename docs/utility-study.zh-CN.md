# 道具收益研究：Windows 数据准备

这套工具用于准备“烟是否帮助过点、闪是否帮助接触”等研究的数据。当前阶段生成观察数据、质量报告和可交回的结果包，**不会直接训练模型，也不会把历史相关性当成收益率**。

## 到那台电脑后怎么做

1. 下载或拉取包含这套工具的 CSBoard 源码，解压到本地普通文件夹。
2. 安装 **Windows x64 Node.js 24 或更新版本、Git for Windows、Go**，使用官方安装程序的默认选项。安装完关闭旧终端。Go 工具链版本由项目 `native/parser/go.mod` 决定，首次运行可能联网下载。
3. 双击 `tools/training/Start.cmd`。第一次自动构建项目锁定版本的解析器，不需要 Electron、Python、CUDA、模型 API Key，也不用启动应用。
4. 把完整对局 `.dem` 放进自动打开的 `.local/utility-study/demos`，可以有子目录。先用 3～5 场 Dust2 检查流程，再增加样本；自录跑图、损坏录像不作为标准对局样本。
5. 回到窗口按任意键。完成后打开结果目录，把最新的 **`csboard-study-日期.tar.gz` 和同名 `.sha256`** 交回来。先交第一批，不必等攒齐所有比赛。

首次准备需要网络；解析过程使用本地文件，不会上传 Demo、访问模型服务或调用 GPU。Windows 若没有 `tar`，需启用系统自带的 tar 或安装提供 tar 的工具并加入 PATH。

遇到失败先保存窗口错误。单份解析失败会继续下一份，部分成功也会生成结果包，并以非零状态提示。正常完成后重复执行会核对已完成文件的校验值并续跑；不要同时启动两次。强制关机留下 `running.lock` 时，先确认任务和解析器进程均退出，再删除 `.local/utility-study/running.lock`。

## 已有开发环境

```sh
make study ARGS=--prepare
make study
```

Windows 双击入口是这两个命令的便捷包装，支持带空格的项目路径。不要在 Windows ARM64 上使用这个 x64 双击入口。

## 数据怎么准备更有用

- 同一地图收集不同队伍、不同经济和不同结果的完整比赛，保留投得好、投得不好和未投道具的情况。
- 不要只挑精彩片段、获胜回合或同一支强队；第一批先检查，再根据缺口扩充。
- 同一场系列赛的不同地图应归到同一组，避免训练和验收重复见到相同队伍交手条件。
- 保存原始 Demo，结果包不包含原始文件；后续可能需要复查具体回合。

## 配置

复制 `config/training/utility-study.example.json` 到 `.local/utility-study/config.json`，修改后执行：

```sh
make study ARGS="--config .local/utility-study/config.json"
```

或者在 Windows 的项目终端执行 `node scripts/training/run.js --config .local/utility-study/config.json`。双击入口使用默认配置。

| 配置 | 默认值与含义 |
| --- | --- |
| `input` / `output` | Demo 输入目录和结果目录，均可填写绝对路径 |
| `maps` | 空数组保留所有地图；如 `["de_dust2"]` 则只保留该图，当前在解析后筛选 |
| `sampleRate` | 4Hz 玩家状态；不是提高游戏 tick，也不降低事件时间精度 |
| `windowSeconds` | 每 2 秒生成一个队伍决策窗口 |
| `horizonsSeconds` | 记录之后 3、5、10 秒的结果，回合提前结束时标记截尾 |
| `threads` | 单份解析使用 4 个线程；始终一次一份 Demo |
| `goMemoryMiB` | 3072MiB Go GC 软目标，不是整个进程内存硬限制 |
| `nodeMemoryMiB` | 4096MiB Node 旧生代堆限制，不包含所有原生与 Buffer 内存 |
| `timeoutMinutes` | 单份 Demo 最长 60 分钟，超时终止其进程树 |
| `maxDemoMiB` | 超过 2048MiB 的单份 Demo 先跳过，可在了解内存需求后修改 |
| `matchGroups` | 以输入目录下相对文件路径为键，填同一场/系列赛的组名 |

例如 `"matchGroups": {"series-a/map1.dem": "series-a", "series-a/map2.dem": "series-a"}`。分组名不进入分享包，只导出令牌。配置、解析器二进制或采集代码改变会生成新的数据批次，不混用旧结果。

32GB 内存机器建议先维持默认值、关闭 CSBoard 和其他重型应用；不要因为有 16GB 显存就提高解析并发。磁盘空间不足时会停止并保留断点。输出体积取决于烟体素和比赛长度，工具生成压缩包时还需要额外空间。

## 结果内容与边界

- `manifest.json`、`SUMMARY.txt`：机器配置、成功/失败数、地图数据清单、训练/验证/测试分组。
- 每份 Demo 的 `report.json`：解析器信息、地图版本、回合、窗口、道具事件数量和缺失情况。
- `windows.jsonl.gz`：严格取锚点前的己方状态；后续动作与结果单独存放。敌方全知状态位于 `privileged`，不能直接作为在线推荐输入。
- `events.jsonl.gz`：筛选字段的死亡、伤害、致盲、投掷等原始事件；缺失字段保持缺失。
- `round-*-states.jsonl.gz`：玩家位置、朝向、健康、装备等回放状态。
- `round-*-effects.jsonl.gz`：实录烟雾体素和火区，不用默认球体替代。
- `round-*-projectiles.jsonl.gz`：投射物轨迹，用于后续关联投掷与效果。
- `complete.json`：完整性校验和采集指纹，支持安全续跑。

玩家名称、Steam ID 使用本地密钥生成令牌，不导出语音、聊天、服务器地址、原始文件路径和身份映射。**这不是不可识别的数据**：坐标、时间和行为仍可能关联原比赛。只分享工具生成的包，不分享整个 `.local`、`identity.key` 或工作任务文件。

同一 Demo 的所有窗口保持在同一数据分组。默认按组哈希分为约 80%/10%/10%，小样本可能缺某个分组；不能直接据此报告模型成绩。窗口相互重叠，不能把窗口数量当成独立比赛数量。

当前缺少可见性/听觉信息重建、因果对照与人工战术评价；“下一秒没有投掷”不意味着场上没有已生效的烟或其他道具。事件队伍缺失和观察期截尾会显式记录，不能把未知值当作零死亡。拿到第一批结果后，先进行数据质量审查，再确定风险模型与收益估计的训练方案。


## 致盲采集修正（数据格式 2）

旧版可能只有闪光爆炸，没有致盲事件。新版同时转接解析器的 `PlayerFlashed`，补全受害者、可用的投掷者、有效致盲时长（秒）和投射物标识，并与原始 `player_blind` 去重。缺失身份、时长或实体关联保持未知；上游对同帧多闪的归属判断仍可能存在歧义，不能据此认定战术因果收益。

Windows 双击入口每次先构建当前解析器，避免源码已更新却继续运行旧二进制。更新代码后，使用原来的 Demo 目录再次执行即可；新版结果独立保存，不覆盖旧批次。已有结果包无法精确补回缺失事件，需保留原始 Demo。

报告新增 `qualityWarnings`：有闪光爆炸但零致盲事件，或所有致盲记录均缺失时长时，窗口和报告都会提示。警告表示需要检查数据，不等同于确认解析失败（例如确实无人被闪的录像）。
