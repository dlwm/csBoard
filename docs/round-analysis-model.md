# 单回合模型分析接入

仅桌面版提供 AI 教程及 WebMCP 工具，网页版不显示入口，也不注册工具。沿用现有 WebMCP 接入，不增加模型服务或自动上传。先在数据分析中选择选手和 Demo，再让已连接的用户模型调用：

用户可直接要求模型：“分析这场比赛第 8 回合，重点看进攻方原意、CT 是否被道具引走、回防时机，以及有哪些改进空间。”模型应先确认准确的 Demo ID，不能仅凭重复的文件名或回合号选择数据。

1. `get_analysis_context`：从 `roundAnalysis.availableDemos` 获取准确的 Demo ID 和回合号。
2. `get_round_analysis({demoId, round, dataset: "context"})`：获取回合范围、阵容、数据覆盖和分析提示词。
3. 分别请求 `timeline`、`events`、`utility`，按 `pagination.nextOffset` 翻页直到 `hasMore=false`。

```json
{
  "demoId": "从上下文取得的真实 ID",
  "round": 8,
  "dataset": "timeline",
  "startSeconds": 15,
  "endSeconds": 35,
  "sampleSeconds": 0.25,
  "limit": 20,
  "offset": 0
}
```

- 时间从冻结结束计算；负数表示冻结时间。tick 为原始 Demo tick，不是多 Demo 分析合并后的偏移 tick。
- 单回合接口保留双方所有选手，不沿用选手、阵营、经济和道具类别过滤，避免丢失回防、牵制和持包人的证据。
- 时间线默认每秒一个已有快照，可改为 0.25–5 秒；不会生成源数据中没有的帧。每页最多 100 条。
- 道具默认不返回轨迹；`includeTrajectories:true` 时每次投掷最多返回 65 个采样点，并标明原采样数。没有轨迹或无法配对的投掷仍可从事件流检查；空道具列表不等于没有投掷。
- 所有坐标统一为场景米制坐标：x 对应游戏 Y，y 对应高度 Z，z 对应游戏 X。缺失坐标为 null。
- 接口只读，不切回合、不调整镜头。截图是当前回放与镜头，不会自动对应请求的回合。

建议分析结构：开局布置 → 试探与道具 → CT 调动 → 执行/转点 → 下包与回防。每个问题列出具体时间、选手、记录 ID、支持证据、反证、置信程度和改进方案。

“进攻原意”“被假打引诱”“识破”只能是候选解释。位置变化不自动证明回防或被引诱；必须考虑持包人、道具时序、闪光伤害和交火，也要考虑常规补防等其他解释。Demo 的全知位置不代表玩家当时知道敌人位置，不包含语音、完整听觉或精确视线证据；不要根据最终输赢倒推意图和决策质量。
