# NAV 地名标注

运行 `make nav-labels`，打开终端中的本地地址。

1. 在 3D NAV 视图中选地图，按需筛选楼层或高度，点击“新区域”，填写名称、别名（逗号分隔）。
2. 左键涂画完整 NAV 单元，Shift 或擦除模式移除标注；右键旋转、中键平移，滚轮缩放；“俯视”可快速对齐顶部视角。
3. 点击“保存到项目”，生成 `src/data/mapPlaces/<map>.json`，重新构建应用后地点查询生效。

笔刷通过三维射线只选中可见地面，隐藏的下层不会被穿透涂画。一次笔划会跟随坡面高度，遇到超过 64 Source 单位的高度跳变需松开后重新点击，避免误涂另一层。这个阈值可在 view3d.js 中调整。

支持撤销、重做、JSON 导入导出。上下层或坡度可用 Z 范围进一步限制笔刷。改变归属会将单元从旧区域移动到新区域。

标注带 NAV 指纹；地图几何更新后不能静默复用旧编号。数据表示区域范围，不保证掩体、可见性或每个代表点可站立。工具只在本机运行，不加入应用或发布构建。

自动导入从 CS2 地图的 `env_cs_place` 实体及其模型边界提取，再依据真实三维凸体积映射到 NAV 生成同一格式（`source: game_place_volume`）。人工标注用于补充别名和更细报点；不要把官方区域等同于完整的社区报点体系。

地点工具的名称目录会包含这些标注；按名称查询返回区域内的 NAV 多边形和高度。返回代表点数量有限制，完整区域归属保留在标注数据中。已导入地图包含官方英文地点数据；中文别名和更细的社区报点可人工补充。

## 出生区域与出生点

- “＋ T / CT 出生区”创建出生区域，用笔刷涂选范围。出生区域和普通地名区域可叠加；同一层分类内一个 NAV 单元只能属于一个区域。
- 选择阵营，点击“添加出生点”，随后点击三维地面，可连续添加多个点。T 为橙色，CT 为蓝色，箭头表示朝向。
- 点击点位或列表项可以修改名称、阵营和朝向；“重新定位”后点击地面移动，“聚焦”可放大查看。
- 在同阵营出生区内添加或移动的点会自动关联区域；也可以选择未关联。区域删改后失效的关联会解除，点位保留。
- 出生点保存真实 Source XYZ、朝向（0° 指向 Source +X，90° 指向 +Y）、NAV 编号和所属区域，地点查询不会用 NAV 中心替换出生坐标。

旧地名文件仍可读取；新增字段为区域的 kind/team 和顶层 spawnPoints。source 区分人工标记和地图实体来源，不把人工坐标标为已验证游戏实体。


## 从本地 VPK 自动导入

将地图 VPK 放入 .local/maps，运行：

```bash
make map-places
make map-places ARGS="--map de_dust2"
# 仅在需要时同步 VPK 中配套的 NAV；原 NAV 备份在 .local/map-annotations/<map>/。
make map-places ARGS="--sync-nav"
```

只提取实体、NAV 和区域碰撞体，不导出世界模型或贴图。需要的 Source 2 Viewer 自动使用项目固定版本及校验和。

- 地名来自 env_cs_place，出生点来自 info_player_terrorist / info_player_counterterrorist，埋包范围来自 func_bomb_target（A/B）。
- 出生区使用官方 TSpawn / CTSpawn 地名范围，购买区来自 func_buyzone，分类独立。官方地名范围外的出生点按实际所在 NAV 单元生成候选出生范围（game_spawn_nav_cells），明确标记为未确认，不扩张为外围包围盒。
- 地名用 NAV 中心上方 16 Source 单位，薄埋包／购买触发区用地面及其上方 16/32 单位检测原始凸体积（含旋转和缩放），保留高度；边界附近仍按完整 NAV 单元归属，不表示精确裁切后的区域边界。
- 出生点的 position 是相同 XY 的 NAV 地面投影，entityOrigin/ entityAngles 保留游戏原始坐标和角度，同时保存 priority、enabled、targetName 和实体编号。
- 自动出生点仅保留默认启用、每队最低优先级的主池，排除名称明确标为 2v2、休闲等额外模式的点。部分地图的竞技随机出生池超过五个，不按数量截断。原始全部实体保存在本地提取目录的 all-spawn-entities.json；具体回合选用哪些点仍由游戏决定。优先级依据：[CS2 FGD](https://github.com/SteamTracking/GameTracking-CS2/blob/master/game/csgo/csgo.fgd)。
- 在 3D 工具修改区域或点位后，记录转为人工标注。重复导入保留这些人工记录；删除自动记录后再次导入会重新生成。
- --sync-nav 遇到旧 NAV 上的人工标注会停止，避免静默换编号。无法匹配的出生点或不支持的区域体积记录到 .local/map-annotations 的报告中，命令以非零状态提醒。

主视图默认展示竞技出生位、包点、购买区。区域按真实触发体积裁切 NAV 三角面，并合并所有有效高度探测结果（0/16/32 Source 单位），避免坡面因首次命中提前退出而出现内部缺口，保留坡度、凹边和孔洞；只沿区域内相连且地面接壤的 NAV 合并轮廓，不跨空隙补桥。导航的跳跃/落差连接不等于连续地面：接壤水平误差 1 Source 单位、台阶高度误差 18 单位，集中在 src/data/regionSurfaces.js。购买区仅保留包含竞技出生点的连通地面，排除额外模式区域和高处孤立块。填色保留真实地面高度，轮廓计算仅对齐 0.25 Source 单位的浮点误差。包点红色并显示 A/B；T 购买区橙色、CT 蓝色，出生位和购买区无文字。淡光与光幕遵循正常深度遮挡及楼层过滤，不沿内部 NAV 接缝生成光墙。

协作面板人物放置和拖动支持出生位及已添加道具起点吸附，鼠标、触控共用逻辑。默认生效；进入距离为 24 Source 单位（约 0.61 米），脱离距离为 36 单位，允许高度差 12 单位，避免跨层吸附；已有人员占用的出生点不参与，道具起点允许多人使用；道具添加时保留速记原始坐标。按 Alt 可临时跳过吸附。阈值集中在 src/three/boardSnap.js。

购买触发体积保留 targetName / enabled 信息；过滤额外模式或禁用体积，并保留竞技主出生池所在或与其连续的购买触发块。道具起点显示可拖动标记，添加和拖动时也支持出生点吸附；按 Alt 临时取消，移动后使用原有撤销与存档流程。

## 模型面简化

设置的“模型面简化”章节按监视器、第一人称、自由视角分别配置，默认均为 0（原始模型）。设置自动保存，按实际视角切换；模型仍遵循原有懒加载策略。界面仅保留面简化，不再提供隐藏小面/细薄物体等实验开关。

使用 Three.js 随附的 meshoptimizer 简化器，只处理实际索引引用的顶点，支持多材质和 drawRange；锁定开放边界，原始碰撞不变。滑块 0–100 对应目标面数比例 max(0.05, 1 - 0.95 × 强度 / 100)，最大世界空间误差 0.4 × 强度 / 100 米。公式见 src/three/modelGeometrySimplifier.js 和 src/three/modelSimplification.js。首次计算显示进度，并临时降低地图刷新频率；每张地图最多缓存三种强度，缓存预算 64 MiB，当前使用的结果保留，超过预算时释放其他缓存。恢复值 0 使用原始几何；卸载地图释放全部派生网格。NAV 地面不参与模型简化。

## 二维地图样式

地图右下方斜边标签切换纯地图与点位地图，正式界面也可用。纯地图保留包点、购买区、竞技出生点；点位地图额外按命名区域配色并显示文字。SVG 和主视图共用 src/data/regionSurfaces.js 的真实触发区裁切，不能以整块 NAV 替代触发区。主视图北向与 SVG 一致（Source X 向右、Y 向上），多层地图并排显示上/下层，共用缩放与旋转，不复制场景或模型；点击按所在视口拾取相应楼层。仅二维显示人员方向三角标，退出后恢复视线。

滚轮或触控板捏合缩放；中键旋转，Shift/Ctrl + 中键平移；Alt + 滚轮及双指旋转也可用。二维不展示模型操作和单层筛选入口。所有转换只影响显示，不改人物、道具或存档数据。
